# Our Solution V1.2：VideoMAE V2 K710 + YOLO 快速验证

日期：2026-11-03  
状态：离线 POC 代码已加入独立研发分支；尚未在负责人 GPU 环境运行，不能宣称识别效果已提升。

## 1. 本轮决策

优先验证一条更直接、计算成本更可控的零训练路线：

**现成 YOLO 人物检测/跟踪 → 连续人物裁剪 → 现成 VideoMAE V2 ViT-Base K710 分类器 → 全视频滑动窗口输出。**

本轮先不把 Qwen3-VL、Video-STAR、X-CLIP 或 InternVideo2 引入主流程。此前 Qwen3-VL / X-CLIP 探针文件暂时保留为独立候选，不是本轮首选路径。

## 2. 零训练边界

- YOLO 使用官方公开 COCO 预训练权重，只做人类检测和跟踪。
- VideoMAE V2 使用作者发布的 ViT-Base K710 蒸馏成品权重，原样加载 710 类分类头。
- 不训练、不微调、不蒸馏、不训练新 head、不拟合融合器或校准器。
- 只允许固定规则、视频帧采样、人物裁剪、窗口长度、窗口步长、padding 和跟踪配置调整。
- 不修改现有六模型路径，不接入 DEV 页面，不修改 main/dev。

## 3. VideoMAE V2 权重与官方配置

- 模型仓库：OpenGVLab/VideoMAE2。
- checkpoint：distill/vit_b_k710_dl_from_giant.pth。
- 文件大小：174 MB。
- 官方模型仓库许可标记：Apache-2.0。
- 官方模型库报告：K710 Top-1 81.5%。
- 官方评测配置：16 帧 × 5 时间片段 × 3 空间裁剪。
- 本项目采用 ViT-Base、710 类、16 帧、224×224、tubelet size 2。
- 脚本验证 checkpoint SHA256：8141a6955e0700d11bf15928fe6d61e5cfe482606fed8cfdddb1b922c0fd88ec。
- 类别索引从官方 misc/label_map_k710.txt 复制并保持原顺序；本项目文件不重新排序。

官方 81.5% 是 K710 基准结果，不能当作我们自拍视频的预期准确率。快速 POC 只使用一个中心空间裁剪，计算设置与官方 5×3 测试不同。

## 4. 人物检测与连续输入

- 首轮检测器：YOLO11s COCO 预训练权重，仅检测 person 类。
- 跟踪器：ByteTrack。
- 主人物选择：依据轨迹持续性、平均人物框面积和中心性进行固定规则选择；可用 person-id 参数指定 ID。
- 轨迹短暂丢失：仅对短间隔做插值和平滑；长时间丢失时跳过人物裁剪窗口，不跳接其他人物。
- 人物裁剪：正方形上下文窗口，默认在人物最大边长两侧各增加 25% padding；保留头部、手部和近身物体。
- 对照输入：原始完整画面和人物裁剪使用同一批时间帧、同一 VideoMAE 权重和相同预处理。

YOLO11s/Ultralytics 默认 AGPL-3.0。当前只用于内部学术验证；公开服务或闭源部署前必须完成许可审查。若不适用，应替换检测器适配器，不影响 VideoMAE 主实验。

## 5. 连续视频分析设置

- 采样率：默认 7.5 FPS。
- 每个分类窗口：16 帧，约 2 秒时间跨度。
- 滑动步长：默认 0.5 秒，窗口重叠。
- 完整视频从头到尾处理；不限制固定 8 秒。
- 末尾窗口对齐最后一段视频；不足 16 帧时使用边界帧填充并在结果解释时标明。
- 每个窗口输出 K710 原生 Top-5 类别和 710 类 softmax 分数。
- 分数仅为分类头输出，不称为校准概率或目标域准确率。
- 时间区间是滑动窗口的近似区间，不宣称逐帧精确定位。

## 6. 对照实验

### R0：完整画面基线
直接将完整画面的 16 帧输入 VideoMAE V2。

### R1：人物裁剪
将 YOLO 跟踪得到的同一人物裁剪输入相同 VideoMAE V2。

### R2：连续时间轴
对比不同窗口步长：
- 2.0 秒：低重叠/近似不重叠；
- 1.0 秒：中等重叠；
- 0.5 秒：高重叠，默认。

### R3：裁剪质量敏感性
固定同一视频、权重和窗口，比较人物框 padding：
- 15%；
- 25%；
- 40%。

只在少量配置验证视频上选择默认值。冻结后再对独立样例检查，不在同一批视频上反复调参并宣称准确率。

### R4：跟踪稳定性
检查：
- 主人物 ID 是否稳定；
- 遮挡/出画时是否拒识；
- 是否错误切换到旁人；
- 头、手和手机是否仍处于裁剪画面中。

## 7. 首轮验证视频

优先从已有实拍样例中选：
1. 看手机；
2. 手机通话；
3. 挥手；
4. 睡姿/睡觉；
5. 吃东西；
6. 摔倒。

其中 K710 对 looking at phone、talking on cell phone、waving hand、sleeping 有原生类别；吃东西和摔倒必须按具体 K710 原生标签解释。不能将 eating burger 等子类改称通用 eating food，也不能将 faceplanting / falling off chair 改称通用 falling down。

如果 uploaded plan 中提到的 10 个目标名称包含其他类别，须先用官方 label map 逐项精确核验大小写、空格和语义，再列入 exact-match 评估；不能凭近义词推定覆盖。

## 9. 放行标准

首轮只回答“这条路线是否值得继续”，至少核验：

1. 官方 checkpoint 能否在目标 GPU 正确加载，710 类 head 与官方 label map 对齐。
2. YOLO 是否能稳定跟踪主要人物。
3. 人物裁剪是否比完整画面更常把精确目标标签排到前列。
4. 滑动窗口是否能反映动作变化，时间轴是否连续。
5. 模型加载时间、每窗口耗时、整段视频耗时和峰值显存是否可接受。
6. 长时间遮挡或跟踪丢失时是否能正确跳过/拒识，而不是误切换人物。

任一关键环节失败，先报告具体错误，不通过训练、微调或更换分类头来补救。
