## 从一个真正想知道的问题开始

论文不是需要“读完”的清单，而是把好奇心变成可验证问题的工具。先选择一个你愿意追下去的问题，再进入对应章节：

| 如果你好奇…… | 可以继续追问 | 第一站 |
| --- | --- | --- |
| 模型能否不依赖传统 OCR 直接读懂文档？ | 端到端方法在哪些页面上更好，又会在哪里失效？ | [文档智能](02_document-ai.md) |
| 为什么模型看见了文字，却仍理解错表格和版面？ | 空间位置、阅读顺序和结构表示分别贡献了什么？ | [DocTags 与结构化文档](04_doctags.md) |
| 同一个 VLM 能否从单页文档走向连续视频？ | 从空间理解扩展到时间、事件与证据定位，还缺少哪些能力？ | [视觉语言模型](03_vlm.md) |
| Benchmark 分数更高，是否真的更有用？ | 指标能否覆盖真实任务、失败成本和用户体验？ | [评测基准](05_benchmark-2026.md) |

!!! note "当前主线与未来延伸"
    现有导读以文档理解和 VLM 为主。视频理解将作为后续扩展方向；现在可以先建立视觉—语言对齐、证据定位和可靠评测等共通能力。

## 推荐阅读顺序

```text
综述：确定任务边界与关键词
        ↓
基础模型：补足必要概念
        ↓
Document AI / VLM：理解方法与主张
        ↓
DocTags / Docling：连接结构化文档实践
        ↓
Benchmark：检查证据是否支持主张
        ↓
Week 11：选择一项可缩小复现的工作
```

## 选择一次探索任务

| 可用时间 | 不必“读完”，只需完成 | 你将带走什么 |
| --- | --- | --- |
| 30 分钟 | 看摘要、方法图和限制，写下 3 个仍未解决的问题 | 一张问题卡 |
| 2 小时 | 追踪论文中的一个主张，核对数据、指标和代码入口 | 一条证据链 |
| 1 周 | 选择最小主张，先写成功标准，再完成一次小规模复现 | 可验证的研究记录 |

## 每篇论文至少回答六个问题

1. 研究问题是什么，明确的非目标是什么？
2. 方法相对 baseline 只改变了什么？
3. 数据来源、划分、许可和潜在偏差是什么？
4. 主指标是否真的对应研究问题？
5. 哪个消融或失败案例最能支持或削弱主张？
6. 在你的资源上，哪一个最小主张可以被复现？
