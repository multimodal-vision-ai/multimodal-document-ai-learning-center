    Qwen3.5-0.8B 多模态推理入门¶

    官方模型 ID：Qwen/Qwen3.5-0.8B
    对应课程：Week 4｜Vision-Language Models
    预计时间：2–3 小时

    Qwen3.5-0.8B 是统一处理文本与视觉输入的轻量级模型。本页不复制容易过时的完整 API 教程，而是帮助你从官方 Model Card 出发，完成一次可复现的文档图像推理与失败分析。

    名称说明

    课程早期材料曾使用“Qwen3.5-VL-0.8B”作为教学名称。实际下载与代码中应使用官方模型 ID Qwen/Qwen3.5-0.8B，避免得到错误或非官方模型。

    模块学习卡与完成路径¶

    字段 本页约定
    对应周次 Week 4
    适合谁 已完成 Python 环境和 Transformers 基础，准备首次 VLM 推理的学生
    预计时间 最小 2–3 小时
    学什么 官方模型选择、多模态输入、generation config 与文档图像失败分析
    官方来源 Qwen Model Card、QwenLM 官方组织与 Transformers 官方文档
    最小动作 用官方 ID 对一张普通图片和一张文档图片完成推理
    提交证据 metadata、代码/Notebook、两组原始输出、对照和失败分析
    完成自查 能解释模型版本、输入格式、输出限制和一个文档失败案例
    下一步 返回 Week 4完成受控实验
    路径 完成范围
    最小 跑通官方最小示例和一张文档图片，保存原始输出
    标准 完成两类图片、一个单变量对照、失败分析和最低提交物
    进阶 增加固定文档切片、第二个模型 baseline 或结构化评测

    运行契约¶

    项目 约定
    前置条件 Python/Transformers 环境；已读 Model Card；公开或自制图片；足够内存/显存或免费云端环境
    唯一入口 Qwen/Qwen3.5-0.8B 官方 Model Card中的当前最小示例
    版本 固定模型 ID/revision，记录 Python、PyTorch、Transformers、相关 processor package、CUDA 与设备
    预计耗时 2–3 小时，包括环境确认、两次推理、对照和失败记录
    算力与成本 GPU 可选；显存不足时使用 CPU、官方托管推理或免费 Kaggle；不要求付费资源
    输入 一张普通图片、一张公开/自制文档图片、固定 prompt 与 generation config
    预期输出 run-metadata.md、inference.py/Notebook、outputs/ 原始结果和 analysis.md
    成功判定 从头运行成功，两类输入和配置可追溯，至少解释一个失败案例
    常见失败与恢复 模型类错误时核对 Model Card 与依赖；OOM 时缩小输入/生成长度或换环境；格式不稳时只改变一个生成参数做对照

    学习目标¶

    完成本页后，你应能：

    • 从官方 Model Card 判断模型输入格式、license 与限制；
    • 使用 Transformers 运行一张普通图片和一张文档图片；
    • 保存模型 revision、环境、prompt、generation config 与原始输出；
    • 分析 OCR、表格、阅读顺序或幻觉方面的失败案例。

    开始前检查¶

    • 已完成Python 环境与Transformers 基础；
    • Python、PyTorch、Transformers 与 CUDA 组合遵循官方页面要求；
    • GPU 显存不足时可先使用官方托管推理、Kaggle，或仅阅读并设计实验；
    • 不使用含隐私、身份信息或未授权内容的文档。

    不要盲目安装“最新版”

    多模态模型的加载类和依赖会变化。先读取 Model Card 的当前安装命令，再把实际成功运行的版本写入实验记录；不要把本页当作永久有效的版本锁定文件。

    官方入口¶

    以下内容按顺序阅读：

    1. Qwen/Qwen3.5-0.8B Model Card（模型 ID、用法、license、评测）
    2. QwenLM 官方 GitHub 组织（官方代码与相关项目）
    3. Transformers multimodal chat templates（多模态消息格式）
    4. Transformers installation（当前安装与环境要求）

    最小实验¶

    1. 建立实验清单¶

    在运行代码前创建 run-metadata.md，记录：

    model_id: Qwen/Qwen3.5-0.8B
model_revision: <commit hash>
python: <version>
torch: <version>
transformers: <version>
device: <CPU/GPU>
seed: 42

    模型 revision 可从 Model Card 的文件历史或本地缓存信息获取。不要只写“latest”。

    2. 运行官方最小示例¶

    从 Model Card 复制当前的 Transformers 示例并保存为 qwen35_inference.py 或 notebook。首次只运行官方图片，确认以下四个阶段均成功：

    message（图像 + 文本）
        ↓
processor.apply_chat_template
        ↓
model.generate
        ↓
decode 新生成 token

    运行成功后，将代码改为接收本地图片路径，但不要修改模型内部实现。

    3. 运行文档图像¶

    选择一张公开或自制的文档图片，至少提出三类问题：

    1. OCR：逐行读取一段文字；
    2. Structure：描述标题、段落、表格及阅读顺序；
    3. Grounded QA：回答一个只能由图片内容支持的问题。

    每次运行保存：图片来源、完整 prompt、generation config、原始输出、运行时间与显存（如适用）。

    4. 设计对照¶

    保持图像和 generation config 不变，只修改 prompt：

    Run Prompt 特征 观察指标
    A 简短通用指令 信息完整度、幻觉
    B 明确输出字段 格式遵循、漏项
    C 要求“不确定时说明” 无依据回答数量

    不要同时修改多个因素，否则无法解释差异来自哪里。

    最低提交物¶

    week04/
├── README.md
├── qwen35_inference.py        # 或可从头运行的 notebook
├── run-metadata.md
├── prompts.md
├── results/
└── failure-analysis.md

    README 必须包含唯一运行入口。若样例图片不能重新分发，应给出来源与准备方法，而不是提交受限文件。

    自主完成标准¶

    • 代码使用准确的官方模型 ID；
    • 模型 revision 与依赖版本可追溯；
    • 至少完成普通图像与文档图像各一次推理；
    • 原始输入、prompt、配置和输出成对保存；
    • 至少分析 3 个失败案例，包含证据和可能原因；
    • 学生能解释 processor、chat template、generate 与 decode 的作用。

    常见问题¶

    加载时提示找不到模型类¶

    通常是 Transformers 版本与 Model Card 要求不一致。回到官方 Model Card 核对安装命令，不要通过猜测类名绕过错误。

    CUDA out of memory¶

    先关闭其他 GPU 进程、减小输入图像尺寸或 generation 长度；仍无法运行时使用更合适的平台。不要在未理解精度影响的情况下随意更改 dtype 或量化配置。

    输出内容正确但格式不稳定¶

    先固定 generation config，再提高 prompt 的字段约束；保存失败样例，不要人工修改模型输出后当作原始结果。

    可以直接把模型输出当 OCR ground truth 吗？¶

    不可以。模型输出只能作为 prediction。Ground truth 应来自可靠标注，并与测试数据管理流程分离。
